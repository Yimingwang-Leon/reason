# 红队复查:猎物定位盲区(RFT/GRPO 的靶子打错了吗?)

**复查员角度**:猎物定位盲区 | **铁律**:只读本地+联网,$0,无提交 | **日期** 2026-06-12
**一句话结论**:团队的"RFT DEAD"结案在**它实际打的那批猎物上是对的**(已被我独立验数),但**它从未在对 run-011 干净的分布上定位过真实 R-loss**——这个盲区是真的。只是补上盲区后 RFT **大概率仍不复活**,因为我额外发现:① 那 1.6pp gap 在干净模型(run-012)身上是 **2.6pp 且更大**,所以它**不是 run-011 的污染漏题**,而是 holdout↔LB 的**结构性分布外推误差**;② 团队能看见的 bit 失败里 ~95% 是 oracle/歧义损(RL 修不动),不是 R-loss。

---

## 一、独立复核:R2 "净 -1" 的地基是真的(A 级,我亲自数过)

`data/probes/r011_prey_baseline.jsonl`(45 行,temp=0 贪心 = 真实评测条件)按 `reward` 字段重数:

| 猎物类 | run-012 当作猎物 | run-011 贪心**已对** | run-011 真实剩余猎物 |
|---|---|---|---|
| bit_rloss | 11 | **5** | 6 |
| crypt_solver_ok | 26 | **1** | 25(但这是 oracle 损,非 R 损) |
| eq_rloss | 8 | **8(全对!)** | **0** |
| 合计 | 45 | **14** | 31 |

- 团队的 45 猎物全部从 **run-012 的 holdout 失败**圈定。但 run-011 贪心已对其中 14 个,**eq 8/8 全清**。
- 我抽看了 run-011 在 eq 猎物上的轨迹(`04171e29`/`10d7bd1b`):是**真·枚举搜索 CoT**(系统扫候选规则+四种反转模式),**不是记忆复读**。
  → 这坐实:eq 猎物纯粹是 run-011↔run-012 两个 checkpoint 之间的 **R 方差**;run-012 是 eq 上更弱的签,团队**从更弱的模型身上圈了猎物**,拿去喂更强的 run-011,当然净增量 ≈0。
- **判决:RFT 在"它实际打的这批靶"上 DEAD 是对的(SOLID）。靶确实打错了——打的是 run-012 的弱点,run-011 早补上。任务的怀疑①成立。**

## 二、但"为什么打错"团队归错了因——这才是真盲区

团队把 run-011 的 gap(holdout 外推 0.866 vs LB 0.85 = 1.6pp)读作"**污染**:run-011 见过 holdout，所以它在 holdout 没暴露的 LB 题上真丢分，那批才是真猎物"。

我对**干净模型 run-012** 做同样的外推(`data/run012_holdout_decode.jsonl`，run-012 从未见 holdout，A 级干净）:

```
run-012 holdout 各类 acc: bit .827 / eq .764 / crypt .000 / 四健康 1.000
按 holdout 类别权重外推全集 = 0.8658，  vs  run-012 LB = 0.84   → gap = +2.6pp
```

**干净模型 run-012 的 holdout→LB gap = 2.6pp，比 run-011 的 1.6pp 还大。**

→ 这个 gap **不是污染**(干净模型一样有，且更大)。它是 **holdout↔LB 的分布外推误差**:110/cat 抽样的 holdout 把难度估乐观了 + 类别权重外推噪声。run-011 的 gap 反而**比干净模型小**(因为它确实多见了 holdout，污染把它的 holdout 分**抬高**了，反而让它的 gap 看起来小)。
**所以"run-011 的污染漏题 = RFT 该打的真猎物"这条推理链断了——那批题在干净模型上也照丢，不是 run-011 独有，更不是"它见过 holdout 才丢"。**

## 三、真盲区到底在哪:gap 的 2.6pp 藏在两个互斥位置(决定 RFT 生死)

约束:LB(run-012)=0.84，四健康类占 66.8% 权重，crypt 占 8.7%(LB≈0%)。解这个账:

- **H-健康**:四健康类(cipher/gravity/numeral/unit)在 LB 上**不是 100%**,而是 ~96%。它们占 2/3 权重,掉 4pp 就吃掉整个 gap。→ 团队记忆"四健康类 100% oracle"是**110/cat holdout 抽样的零膨胀**(440/440),从未在 LB 未见分布上验过。**若 gap 在此,RFT 无解**(这些类离线 oracle=100%,没猎物可采)。
- **H-bit/eq**:若健康类真 100%、crypt 真 0%,则 bit+eq 在 LB 上的合并 acc 必须 = **0.699**,而 holdout 干净抽样是 0.808 → **bit/eq 在 LB 上比 holdout 低约 11pp**。这正是 RFT/GRPO 该打的地方(bit oracle 92-94%,有 R 头寸;且是真·未见泛化损,非记忆)。

**这就是任务问的真盲区:团队所有猎物只从 holdout 110/cat 干净抽样里捞(bit=.827 那一档),如果 LB bit 真的 ~.70,团队的取景框**根本拍不到 LB 上大头的 bit 失败**——不是打错靶,是**靶场只有 1/6 的真靶进画面**。

## 四、即便补上盲区,RFT 大概率仍不复活——因为可恢复头寸太薄

`data/probes/bit_headroom.json`(23 个 bit 失败的 oracle 解剖):

| 类别 | 占比 | RL 能否修 |
|---|---|---|
| `none`(oracle 连候选都给不出,未建模规则类) | 78% | **否**(oracle 损,不是 R 损) |
| `ambig_ok`(同输入多合法输出,信息论歧义) | 17% | **否**(92.8% 信息论上限,A 级已证) |
| `unique_ok`(唯一候选但模型错 = 真 R-loss) | 4%(1/23) | 是 |

→ 即使把镜头挪到 LB 上更难的 bit 失败,按这个解剖,**~95% 是 oracle/歧义损,RFT 物理上修不动**,只有 ~5% 是可恢复 R-loss。eq 同理:`autoresearch/PATHS.md` 已 A 级记 "eq qop_unseen 缺失的 68% = 0/115 任何单规则可恢复",也是 oracle 损。crypt 25 个真猎物 100% 是 oracle 损(22.5% 硬顶,solver 造不出 trace 喂 RFT)。

## 五、免费近似定位 run-011 真实 LB 失分的手段(回答任务②)

**完全免费(只读)、今天能做的**:
1. **解 gap 归属账(本报告已做一半)**:用 run-012 干净 holdout 反推,已锁定 gap 在"健康类 LB<100%"或"bit/eq LB≈.70"二选一。再免费一步:对 run-012 holdout 解码里**健康类**逐题查 `cap_hit` 和 pred 长度分布,看有无截断/边界征兆——若健康类干净 holdout 真零错且无截断,则 gap 强制落到 H-bit/eq(对 RFT 是好消息,但被第四节的"95% oracle 损"对冲)。
2. **run-013 干净 holdout 解码反推(需付费采样,违铁律,不做)**——但**逻辑上等价于 run-012 已有的解码**(两者都 train_split 训练、对 holdout 干净、LB 都 0.84),所以**不必再花钱采 run-013**,run-012 解码已是干净模型的最佳免费代理。这条要给团队记上:**别为"run-013 干净 holdout"再开一次付费解码,它信息量与 run-012 解码近乎重复。**

**需付费(违铁律,仅登记不执行)**:在 210 个**未解码的干净 holdout bit** + 36 个未解码 eq 上贪心解码 run-012,把 110→320/146 抽样,把 bit/eq 的 LB acc 置信区间从 ±7pp 收到 ±3pp。这能证伪/坐实 H-bit/eq。成本 ~$2-3。**但**:即便坐实,第四节的 95% oracle 损天花板仍在,所以这笔钱**只买"确诊"不买"药",不建议花**。

## 六、真实赔率(回答任务③:干净重定位猎物后 RFT 复活吗)

| 情形 | 概率 | RFT/GRPO 能推到 0.865+ 吗 |
|---|---|---|
| gap 在健康类(H-健康) | ~45% | 否(oracle 100%,无猎物) |
| gap 在 bit/eq 但 95% 是 oracle/歧义损 | ~45% | 否(可恢复 ~5%×24.6% 权重 ≈ +0.3pp,够不到 +1.5pp) |
| gap 在 bit/eq 且可恢复头寸被我低估(n=23 解剖样本太小) | ~10% | 也许 +0.5~0.8pp,仍够不到 0.865 |

**P(干净重定位猎物 → RFT 把 LB 推到 0.865+) ≈ 0.06。** 不是 0(团队"DEAD"略过头),但远不足以翻案。**团队的 RFT 结案在结论上对(不该再投钱),在归因上错了一半(把"分布外推误差"误当"run-011 污染漏题",并默认 holdout 抽样代表 LB)。**

## 给团队的三条 takeaway(免费、可立即入账)

1. **修正记忆/账本**:run-011 的 1.6pp gap **不是污染独有**——干净的 run-012 有 2.6pp 同向 gap,这是 holdout↔LB 结构性外推误差。别再把"run-011 在 LB 真丢、holdout 没暴露的题"当成 RFT 的未开采猎物池;那池子在干净模型上也存在,且主要是 oracle 损。(防"从失败推天花板"的同时,也防"把抽样乐观当真实地板"。)
2. **"四健康类 100%"是 110/cat 抽样零膨胀,从未在 LB 未见分布验证**——这是账本里唯一**真·未被审视**的假设,且占 2/3 权重。它若是 ~96%,单独解释整个 gap。这是比 crypt/bit 更值得用免费手段(本报告第五节1)逼问的点。
3. **不要为 run-013 干净 holdout 再开付费解码**(信息与 run-012 重复);不要为收紧 bit/eq CI 花那 $2-3(只确诊不给药,95% oracle 损天花板压死上限)。

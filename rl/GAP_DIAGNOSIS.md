## 0. 一句话裁决

**不存在"离线 vs 在线系统性差异让别人到 0.87 我们到不了"。真相是反的:我们用了一个错误的等权口径,把自己的真实分系统性【低估】成 79.87%,造成"LB 0.84 比离线高、必有秘密增益"的幻觉。换成真分布权重,离线预测 LB = 86.6%,反而【高估】实际 LB 约 1.6–2.6pp。这 ~2pp 不是判分 bug,不是别人有秘密管道,而是(a)健康类/eq 的 holdout 解码率对真实 LB 偏乐观(同分布 holdout + eq 自认向 holdout 调过参),(b)bit/eq/crypt 的 oracle 与执行没榨干。0.85→0.87 的真实矿点 = bit 出题器规则族覆盖(+19/110 离线可证),不是判分、不是健康类、不是权重错配。**

## 1. 缺口分解:那 ~2pp 到底在哪(每块 pp 量级)

### 1.1 先把"缺口"的真实量级钉死(等权幻觉 → 真权账本)

| 口径 | 算法 | 数值 | 性质 |
|---|---|---|---|
| 等权(110/类×7) | Σ acc / 7 | **79.87%** | ❌ 假象。把 crypt(0 分)从真实 8.66% 抬到 14.29%,凭空多扣 ~5.6pp |
| 真分布权重 | Σ wᵢ·accᵢ(train_cat 9500 题权重) | **86.6%** | ✅ 正确离线预测 |
| 实际 LB | kaggle 开奖 | run-011 **0.85** / run-012/13/05 **0.84** | — |

真权重(train_cat.csv,= LB 1899 题分层镜像,本机复核 sum=1.0):
bit 16.86% / gravity 16.81% / unit 16.78% / cipher 16.59% / numeral 16.59% / **crypt 8.66% / eq 7.71%**。crypt 与 eq 只有半个权重。

**残差(离线预测 − 实际)= +1.6pp(对 run-011)/ +2.6pp(对 run-012/13/05)。方向是离线【高于】LB,不是低于。** 用户感受到的"LB 比离线高"完全是等权 79.87% 这个数造成的记账错觉。

### 1.2 ~2pp 残差的归因分解(最可信)

把 86.6% 拉到 LB 0.84–0.85,需要解释 1.6–2.6pp。三种候选与所需幅度:

| 候选嫌疑 | 需要的幅度 | 证据评级 | 裁决 |
|---|---|---|---|
| **判分口径虚高** | 任意 >0 | **A(铁证)** | **0pp**。路A 770 行 ×4 官方判分变体重打:"我们判对∧官方判错" = **0/770**。唯一分歧(bit 无守卫 +9)方向相反,会让 LB 更高。判分不是缺口来源。 |
| **健康类同分布 holdout 虚高(对 LB 偏乐观)** | 健康类 100%→96.1%(−3.9pp)解释 run-012;或 →97.6%(−2.4pp)解释 run-011 | **C(无法证伪,有间接旁证)** | **~1.0–1.5pp(主嫌但未坐实)**。holdout 与 train 同分布(seed42 分层),健康类 110/110 本就是分布内泛化,LB 抽更难/变体会掉一点。但路C 全量复跑证明现分布下健康类真 100%,无正面 OOD 证据。 |
| **bit/eq oracle+执行虚高(holdout 偏乐观)** | bit/eq 在 LB 比 holdout 再掉若干 | **B(有直接旁证)** | **~0.5–1.0pp**。eq 的 `_MODE_ORDER` 源码自认"learned from the holdout"(`src/reasoners/equation_numeric_deduce.py:130`),decisive 子集 train 69.3% vs holdout 82.1%(**+12.8pp** 过拟合)→ holdout eq oracle 88 是乐观数,LB 上 eq 会比 holdout 76.4% 再低。bit 92.8% 上限亦曾是窄族循环论证(见 §4)。 |
| 权重错配 / LB 更偏 crypt | crypt 占比 8.7%→11.3% | 低 | **~0pp**。holdout 是 seed42 分层锁定,分布即 train,排除。 |

**最可信分解(中心估计):**
```
离线真权预测            86.6%
  − 健康类对LB偏乐观      ~ −1.0 to −1.5pp   (同分布泛化虚高,C级)
  − eq/bit holdout过拟合  ~ −0.5 to −1.0pp   (eq自认调过holdout,B级铁证)
  − 判分口径             0pp                 (A级铁证,0/770)
  − 权重错配             0pp
= 实际 LB              ~ 84–85%             ✅ 与开奖吻合
```

**结论:~2pp 缺口 = 离线对真分布偏乐观(健康类同分布虚高 + eq 向 holdout 过拟合),不是"LB 高于离线的神秘增益",更不是判分管道差异。** 上限层面,真权 oracle 天花板 = 1708/1899 = **89.94%**;run-011 的 0.85 已是真权预测 86.6% 的 **98%** 兑现,执行层几乎榨干,剩余空间在 oracle(crypt 0 分 + bit 族覆盖 + eq 尾部),不在某个"不严谨环节"。

## 4. 诚实结论:新路通向 0.87 的概率 & 与"bit 五轮封顶"的关系

### 4.1 我是不是一直在错地方(bit)死磕,真矿在别处(判分/健康类/权重)?

**不是。三路一致证明:判分、健康类、权重都【不是】可白捡的矿。**
- 判分:0/770 虚高,且唯一分歧方向相反(A 级,彻底钉死)。
- 权重:错配只制造了记账幻觉,纠正后 0pp 可捡。
- 健康类:全量 train 可证 100%,无正面 OOD 证据;LB 偏乐观的 ~1pp 是"修复要重训",不是"免费可捡"。
- **真矿确实还在 bit(+eq 尾部、crypt oracle)——但此前死磕的是【错误的 bit 子问题】(窄族内部消歧),不是 bit 本身。** "bit 92.8%/五轮封顶"是窄规则族循环论证的产物(§2④);换成出题器真实族,holdout oracle 110/110,19 道丢分里 16 道纯族外(npred=1,根本不是歧义)。所以是"在 bit 里挖错了坑",不是"该离开 bit"。

### 4.2 通向 0.87 的概率

| 路线 | 离线证据 | 兑现概率 | 风险 |
|---|---|---|---|
| bit 扩展族(+19 离线 / +2.5pp 理论) | A−(`bit_prior_full.log` $0 可复跑) | **中(0.86 中心,0.87 右尾)** | oracle≠LB 前科累累(bit-EV 0/30、run-006/7/8 R 崩);需 R-probe 闸过才花钱 |
| 健康类提 LB 泛化(教 char_set/词表变体) | 无正面 OOD 证据(路C) | 低 | 现分布已 100%,投机性 |
| crypt | 闭式硬顶 22.5%(已证),满打 +0.4–1.0pp | 低-中 | 单靠它不够冲 pack |

**裁决人对 0.87 的概率估计:单靠 bit 一路 ≈ 0.86 概率高、0.87 概率约 0.2–0.3(需 bit 高兑现 + eq/crypt 搭车同时正向)。结构上 0.85→0.87 = +2pp 需要 bit 族 +2.5pp 几乎满额兑现,而 oracle→LB 的历史兑现率从未到过 100%。这与红队"P≈0.05 结构墙"判决并不矛盾:HOW_OTHERS 把判决从"结构墙"降级为"执行层待验"(G1 probe R / D2 本地 ≥98 / LB 三闸开奖定生死),纪律是 R-probe 不过一分钱不花。**

### 4.3 别人到 0.87 是怎么回事(回答存在性证明)

不是判分口径、不是评测管道差异。机制(HOW_OTHERS.md 证据链):0.86 公开线的共同语料哲学 = **永远把真值写进 \boxed**(模型自生成 CoT 拒绝采样,或"诚实部分分析+真值"scaffold),用几千条小而正确样本把【出题器真实规则先验】教进模型;**我们一直 box solver 自洽答案、从没教过先验**。他们 bit 98-99% = 语料隐式携带正确族先验;我们 19 道错里 17 道 Hamming≤2,正是模型在族外/平局点按错误先验掰的。+19/110 ≈ LB +2.5pp,恰好是 0.85→0.87 的缺口。

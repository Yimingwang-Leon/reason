### 2.3 数学:为什么不能直接平均 A/B,必须 ΔW 空间 + SVD 截回 rank32
- 跨 init 的两个 LoRA,(B₁+B₂)(A₁+A₂)/4 = (ΔW₁+ΔW₂)/4 + 交叉垃圾项 B₁A₂+B₂A₁(随机子空间相关,纯噪声)。**同轨迹(SWA)逐元素平均侥幸可行(A/B 连续相关,昨晚实测不掉分);跨 run 必须合 ΔW = (α/r)·B·A。**
- 比赛硬约束 rank≤32,而 ΔW₁+λΔW₂ 秩 ≤64 ⟹ 用 **QR+小核 SVD 精确低秩分解再截 32**(无需稠密化:QR([B₁,√λB₂])、QR([A₁;√λA₂]ᵀ)、SVD(64×64 核),6004 对矩阵 CPU 全程分钟级)。TIES/DARE 需逐元素操作 ⟹ 该票按模块稠密化(最大单模块 in_proj 10304×2688≈110MB fp32,逐模块流式,Mac 可跑)。
- **能量闸**:记 ρ = ‖ΔW_rank32‖²_F/‖ΔW_rank64‖²_F(逐模块+全局)。λ=0.25 时宿主主导,预期 ρ≥0.97;**ρ<0.90 的配方直接废票不提交**。
- 文献依据:task arithmetic(Ilharco 2022)与 TIES(Yadav 2023)/DARE(Yu 2023:delta 90% 随机置零+rescale 近无损,专治同源 SFT 合并)为跨模型权重合并的标准操作;model soups(Wortsman 2022)+0.5~1.5pp 量级但**前提是同 init 同盆地**——跨 init LoRA 不满足,所以本提案不承诺 soup 量级,只按"低剂量注入、宿主保形"设计;LoRA 专属文献(LoraHub、LoRA-soups)一致结论:**合并在 ΔW 空间做、直接平均 A/B 跨任务/跨 init 不成立**。

## 4. 数字账(a:+X 题从哪来)

记 LB 真值 = oracle×R,1899 题口径,1 题=0.0527pp。

- **宿主(kienngx 0.86)错误池 ≈ 1899×(1−0.86)≈266 题**。按社区配方谱系(huikang 系,crypt 弱)与类难度先验推断构成:crypt ~120-140(165 题的大部)、eq ~25-35、bit ~25-35、4 个确定类 ~0-20。⚠️ 这是 C 级推断——kienngx 的分类 profile 没有任何公开数据,这正是 T-A 是"彩票"而非"工程"的原因。
- **我们的注入源(run-011 ΔW)带什么**(对照 recon_data §3):
  - crypt:22.2% solver 的演绎 trace(holdout 折算 26 个 solver-ok 题;recon_data §3.3 全 id 清单)——宿主若 crypt≈10% 弱区,注入哪怕迁移一半行为 ≈ +10~15 题;
  - eq:全枚举 transcript(run-011 +1pp 的主源,微探针已训题贪心复现 30/30)——宿主 eq 错误池 ~30 题里咬下 1/4 ≈ +7 题;
  - bit:难尾 92.3% oracle trace ≈ +3~8 题。
  - 合计乐观通道 ≈ +20~30 题 ≈ **+1.1~1.6pp**;但权重空间注入的技能迁移率文献上只有"非零、远小于 1"的保证(task-vector 跨域迁移典型打 2-5 折)⟹ **中心预期 +0.2~0.5pp,即显示分大概率仍 0.86,P(跨 0.865 线)≈10%**。
- pass@k→greedy 转化率假设:本路线**不经过采样通道**,无此假设;对应物是"权重插值后宿主 argmax 保持率",T-C 票用真金白银直接测。

## 8. 反遗忘设计(e,权重空间版)

本路线零训练,"遗忘"的对应物是**宿主行为被注入扰动破坏**(锚题=宿主已对的 ~86%)。针对 60 步/8e-5 把锚打到 80% 的教训,等价防护:
1. **宿主保形架构**:不对称合并(宿主全量 + 低剂量注入),λ≤0.5 硬上限,首发 λ=0.25;
2. **范数闸 ±5%**:直接引用 alpha36 的 −1pp/+12.5% 实测标定,这是把"LR 过大伤锚"翻译到权重空间的同款保险丝;
3. **DARE 稀疏注入**(T-A2):90% 置零使扰动作用在宿主参数的 10% 上,机制上限制"锚行为"被改写的面积;
4. **梯级 λ**:任何加注前必须先看低 λ 票的实分,等价于"先探针再全量"。

    B1,A1 = f32(HOST[kB]), f32(HOST[kA]); B2,A2 = f32(INJ[kB]), f32(INJ[kA])
    if args.dare or args.ties:                          # 稠密路径(逐模块,流式)
        D = s1*B1@A1 + lam * transform(s2*B2@A2)        # transform = DARE 置零/rescale 或 TIES sign-election
    else:                                               # 低秩精确路径(免稠密化)

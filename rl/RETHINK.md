## 1. 死刑判决逐条裁定:有没有被过度外推、可免费翻案的?

我把全部判决归三类:**(a) 我复算坐实=真死;(b) 读法过度外推但结论不变;(c) 真未测缺口=已被我亲手补测掉。**

### 1.1 RFT/拒绝采样 DEAD — 复算坐实(A 级真死)
独立复算 `r011_prey_baseline.jsonl`(45 行,temp=0=真实评测条件,reward 字段):
- **run-011 贪心已对 14/45**(bit 5/11、crypt 1/26、**eq 8/8 全清**)。
- eq 8/8 是铁证:RFT 圈的 8 道 eq 猎物,run-011 自己 temp=0 全做对——这些是 run-012 错、run-011 见 holdout 后修复的题。RFT 在底座本就会的题上蒸馏=净增量必≈0。R2 实测 13/45(净 -1)与此一致。
- **裁定:SOLID_DEAD。** 团队"吃光可救 R-loss 题"的结论对;真因更精确=**从更弱的 run-012 圈猎物喂更强的 run-011,猎物定义本身偏了**。这恰好回答了团队最担心的"猎物定位盲区":猎物确实定错了(打的是 run-012 的弱点),但**干净重定位也救不回**——见 §2。

### 1.2 crypt closed-form ≤22.5% / crypt 死区 / crypt synth 3% — 复算坐实(A 级真死)
独立复算 `run012_holdout_decode.jsonl` 的 110 道 crypt:
- **0/110 全错**(确认),**105/110 烧满 7680 token 跑飞**,仅 **3/110 产出任何 boxed**,truth 串只在 7/110 出现(且 77/110 truth ≤3 字符=巧合敏感)。
- 这不是 R 漏点(没有"过程对、box 截断"的题可救),是**纯 oracle 墙**:部署模型在 LB 未见分布上连一个 boxed 都来不及产出。
- **裁定:SOLID_DEAD。** crypt 占 8.7% 权重、是最大单点 sink,但闭式上限 22.5% 已 A 级证,且贪心驮不动(探针 5%、合成复现 3% 已证)。**误杀注册表里"crypt 7% 死路"被翻案过一次,但翻案翻到的是"17.6% live solver",不是"40-70% 可达"——22.5% 硬顶是真的。**

### 1.3 eq qop_unseen 0/115 — 复算坐实,且补了团队没做的逐题解剖(A 级真死)
这是团队**最不彻底**的一块,也是 grpo 红队标的唯一 UNTESTED_GAP(eq 残差 K8 未测)。我直接解剖 26 道 eq holdout 失败:
- **6 runaway(cap_hit)** = qop_unseen 枚举永不收敛;
- **11 oracle_far** = 纯 oracle 失手(pred=7 truth=5548、pred=4 truth=2803,根本不沾边);
- **5 nearmiss** + **4 sign-error**(62 vs -62、28 vs -28、23 vs -23、13 vs /13)。
- 我读了 sign-error 的完整 trace:`-` 运算符**从未在 examples 出现**,模型 fallback 到 `|a-b|`(正数),truth 却是负数——**符号在欠定下不可恢复**;`7ac90433` 模型做了一整套自洽搜索得 23、truth=-23,是**欠定下规则歧义**,不是读法 bug。
- **裁定:SOLID_DEAD。** 团队"eq 未测缺口"我已亲手补测掉:这 26 题里**没有一道是 RL/corpus 可免费救的 R-loss**,全是 oracle/欠定。grpo 红队标的"eq UNTESTED_GAP"——**我现在把它降为 SOLID_DEAD**(逐题解剖,A 级)。这是本次终审唯一一处把"未测"钉成"已死"。

### 1.4 GRPO 连坐 RFT / GRPO 救 marginal +1.0pp — OVEREXTRAPOLATED(读法错,结论对)
独立复算 `m0_harvest.jsonl` × `r011_prey_baseline.jsonl` 交叉表:
- **GRPO 可作用面(贪心错 ∧ pass@8>0)= 7/45**(2 bit + 5 crypt + **0 eq**),与 grpo 红队完全一致。
- 但 2 道 bit 正确答案是**少数派 mode**(30ba0cf4 错6:对2、4fb6838e 错4:对1),锐化要**逆多数票翻盘**;5 道 crypt 是 search-luck(8 采样 boxed 互不相同、60% 无 boxed)。
- **裁定:"连坐"逻辑是跳跃(GRPO 负梯度 ≠ RFT 正梯度),红队驳回连坐对;但 GRPO 有独立死刑。** 提案 +1.0pp 严重乐观:真实可锐化弹药 2 道 bit、要逆多数票、组内 1-2 正样本=高方差弱梯度。叠加 $10 连发车闸(`grpo_loop.py:270` balance<1.3×budget 即 REFUSED)都过不了。**结论=与 RFT 同死,死因不同。**

### 1.5 融合线全族死(0.76/0.83/ERROR) / SWA-ep0-alpha 双胞胎 — 复算坐实(A 级真死)
- 三点剂量单调伤模型(50/50 TIES=0.76=-9pp、λ0.25=0.83、T-C=ERROR);ensemble 红队实测 ΔW=B@A 全局 cos:run-011 vs run-012=**0.247**(独立),vs ep0=**0.946**(双胞胎)。
- **裁定:SOLID_DEAD。** 跨 init 合并引入相关性、损 R;SWA/alpha 与 011 同命。无翻案空间。

### 1.6 R 免费漏点(box 截断/去噪/格式提 R)— 复算坐实(B+→我修为 A 级一处)
realization 红队:45 个"出框判错"行 balanced-box 重提取**恢复 0/45**;crypt early-stop 救≈0;corpus/eval_gate 截断逻辑是 skip-not-truncate(正确)。
- 我复算 bit_headroom:23 道 bit 失败里 **18 道 cls=none**(连候选都生不出=纯 oracle 失手)、只 5 道 truth 在采样里出现、**仅 1 道 truth 是 plurality**(多数票已对=唯一"免费"可得)。即 bit 失败的 ~95% 是 oracle/歧义,可救≤1 题。
- **裁定:SOLID_DEAD（R 这一侧）。** 团队"R 是局部最优"成立。唯一未单测的是 bit +238 脏样本去留,但 bit 信息论上限 92.8% 压死,边际<0.1pp,且只有 LB 才显形(要烧配额)。

## 2. 真正未开采的杠杆?按 P(突破 0.865) 排序

我把"账本里唯一真盲点"(prey 红队标的 67% 权重健康类是否真 100%)拿出来做**决定性 LB 配账**——这是判定"墙还是缝"的核心。

### 2.1 决定性配账:gap 必然存在,但落哪都不是活路
类权重(全 9500 train,A 级):bit 16.9%、gravity/unit/cipher/numeral 各 ~16.7%(**健康类合计 66.8%**)、crypt 8.7%、eq 7.7%。

**run-012(干净模型,从未见 holdout)holdout-decode 外推 = 0.8666,实际 LB = 0.84 → gap 2.66pp。** 这个 gap 在**干净模型**上一样存在(甚至比 run-011 的 1.6pp 还大),**证明 gap 不是污染漏题,是 holdout↔LB 结构性外推误差**(110/cat 抽样零膨胀 + 权重外推噪声)。团队"污染漏题=RFT 未开采猎物池"前提**被证伪**。

解 run-012 LB=0.84 的账(crypt=0 已实测确认):
- **若健康类真 100%**:bit+eq 的 LB 实测必须 =**0.699**(比 holdout-decode 的 0.807 低 **11pp**);
- **若 bit+eq 维持 decode 水平 0.807**:健康类 LB 必须 =**0.960**(比 holdout 低 4pp)。
- 二者互斥,**gap 必落其一**。

**这是缝还是墙?——是墙。** 无论 gap 落哪一侧,对免费/≤$10 手段都不可达:
- **若落健康类**(健康类 LB ~96% 而非 100%):这些类**离线 oracle=100%**(440/440),RL 物理上**没有猎物可采**(贪心错的题离线也没有"对的候选"可蒸/可锐)。而且这 4 类的失分发生在 **LB 未见的更难分布**上——我们**本地无 GPU、无法解码 30B MoE、无 LB 探针**,$0 下这个缺口**不可观测、更不可优化**。这不是"未开采的杠杆",是"看不见也够不着的暗物质"。
- **若落 bit/eq**:bit 失败 95% 是 oracle/歧义(§1.6 实测 18/23 cls=none)、信息论 92.8% 压顶;eq 失败 100% 是 oracle/欠定(§1.3 逐题实测)。可恢复 R-loss 头寸 ≈ 5%×24.6% 权重 ≈ **+0.3pp**,够不到 +1.5pp。

**裁定:67% 权重健康类"是否真 100%"是账本唯一真盲点(我确认它从未在 LB 未见分布验过)——但它是死信号而非活路。** 团队没有低估它,也没有可操作的开采方式。这是结构墙最硬的一块:**我们连失分在哪都无法免费定位,定位了也无猎物可采。**

## 4. 残酷诚实的总结:墙还是方法没找到?

**是墙,不是方法没找到。** 我替用户把每块砖都敲过:

1. **LB = oracle × R 这个分解里,两侧都到顶了。** R≈0.96-0.97 是局部最优(R 免费恢复=0,实测);oracle 的可恢复部分(bit 92.8% 信息论顶、eq qop_unseen 0/115、crypt 22.5% 闭式顶)团队已 A 级吃干。剩下的失分**主体是 oracle/歧义/欠定**——这些是**数据生成器的信息论性质**,不是模型能学会的"过程",RL/SFT/融合都翻不动。

2. **最硬的一块墙是"看不见的墙":** 解 LB=0.84/0.85 的账,有 ≈2-3pp 失分**必然落在某处**(健康类 LB<100% 或 bit/eq LB<holdout),但因为**本地无 GPU、无法解码 30B MoE、$0 不能开 LB 探针**,我们**连这部分失分在哪个类都无法免费定位**。即使定位到健康类,那些类离线 oracle=100%、**没有任何猎物可供 RL 采**——物理上无解。这是结构墙,不是懒。

3. **两天的"离线假象"前科已被根因解释:** 融合死于跨 init 相关性伤 R(cos 实测);RFT 死于从更弱模型圈猎物喂更强模型(eq 8/8 已对的铁证)。**这两个不是运气差,是机制必然**——所以我对它们的死刑有信心,不是"再试一次可能活"。

4. **唯一不甘心的出口(诚实给):** 真正没被 $0 关闭的缝**只有一个**——健康类在 LB 未见分布上到底丢在哪。但关闭它需要花钱跑 LB 解码(违铁律)或买 GPU 本地解码(超预算),且即便打开**也大概率是无猎物的 oracle 墙**。**这不是"下一步免费做什么能突破",而是"这条缝的钥匙不在 $0 工具箱里,且锁后面大概率还是墙"。**

**给用户的话:** 你不甘心是对的——0.85 确实不是"模型上限",账面 oracle ~0.90。但 0.85→0.87 这 2pp 的**具体位置**,在我们能用 $0 触达的所有数据里,**全部指向 oracle/欠定损或不可观测的 LB 分布外失分**。两天的失败不是"方法没找全",是**把可达的 oracle 都吃干后,撞上了信息论硬墙**。理性动作:**锁 run-011 + 选最独立第二支签(免费右尾期权),停止为 0.87 花钱。** 不是安慰,是账。

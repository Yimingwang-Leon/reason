### F2. 40 题锚探针的统计功效不够,熔断保不住钱(能保住地板的另有其物)

锚存量 ≈ 84pp(holdout ~1600 已对题)。二项功效计算:
- 锚面真实回撤 **3%**(≈ -2.5pp LB,已 3 倍于各案中心增益):40 题探针触发"≥4 题回撤"线的概率 **每次仅 ~3%**;6 次探针累计 ~17%。
- 回撤 **5%**(≈ -4.2pp):单次触发概率 ~14%,6 次累计 ~59%。
即:一次足以抹掉全部预期收益 3 倍的隐性遗忘,大概率全程探针无声通过,$145/腿照烧。**01 的"≥4/40 才熔断"(允许 10%)与 02 的"<36/40"(允许 10%)都过松;05 的 G2 用 200 锚 ≥98% 才是正确量级。**
- 修法(对 01/02/03 统一):10 步级探针扩到 **150-200 题**(成本 $0.4-0.5/次,相对 $2.4/步是零头),触发线收紧到**净回撤 ≥3%**;并把探针解码顺手算两个免费早期预警量:**平均生成长度漂移**与**重复 n-gram 率**(风格塌缩/复读机化先于答案错出现,这是 greedy 评测下熵塌缩的实际显形)。
- 公正地说:**0.85/0.86 地板不靠熔断保,靠"run-011 永不覆盖 + 不达标不提交 + final selection 取 max"结构性保住**——五案这一层都成立。熔断保护的是**预算与时间**,按上述修法修。

### F3. eq/bit 已对题不在任何 10 步级熔断探针里——eq 枚举风格是头号误伤对象

01("4 健康类各 10")、03("cipher/gravity/numeral/unit 已对锚题")的探针都**不含 eq 与 bit 已对题**。而:
- eq 全枚举 transcript 是 run-011 +1pp 的主源(PATHS 误杀注册表原文);
- 01 对 crypt 截断 rollout 的负 advantage、03 对 crypt 贪心 trace(=枚举式死循环开局)的 rejected 梯度,打压的恰是**枚举式长 trace 风格**;LoRA rank-32 是低秩全局方向,"压制枚举开局"极易跨类泄染到 eq;
- 01 不做长度归一(Dr.GRPO),crypt 混合组里 7680-token 截断负样本的 token 质量是 ~2k 正样本的 3-4 倍,负向风格压力天然占优。
**修法:eq 已对题与 bit 已对题各 ≥40 题进 10 步级探针;预登记"eq spot 净回撤 ≥3 题 → 与锚熔断同级处置"。**(01 训练池巩固层里有 bit/eq,可产生纠正梯度,这点设计是好的;缺的是**监测**。)

### F4. 地板是 0.86 不是 0.85,所有"证伪线/升级闸"的基准要重写

### F5. LB 显示粒度 0.01,把 ±0.3pp 级的 LB 闸全部判为不可读

04 自己写明"显示粒度 0.01,±0.005 盲区"(A 级)。但 02 的 P4(中心 0.855、止损 ≤0.850)与 03 的 P4(LB ≥0.853 才继续)**都把判停条件设在仪器分辨率以下**:+0.4pp 真增益显示 0.85 → 误杀;+0.0pp 显示 0.85 → 误放。修法:LB 只做 0.01 粒度的粗仲裁(≥0.86 算实质信号),**0.3-0.8pp 级的去留判据全部改由 holdout 猎物逐题翻转数承担**(它能分辨 ±2 题),并预登记 holdout→LB 折扣后的换算。

### F6. 回滚的真伪:API 可行,但三个案子的"save→probe"顺序会把坏权重当回滚点

- API 层面回滚是真的:`save_state(ttl 7d)` + `create_training_client_from_state`(weights-only,fresh Adam)已被 recon_tinker 核实,无虚言。
- 但 **01 伪代码(:249-252)与 03 伪代码(:168)都是同一步先 `save_state` 再跑锚探针**:探针失败时,"最新 checkpoint"正是刚存的坏权重。05 的 R1 骨架更糟:循环里**根本没有 save_state**,`rollback()` 无目标可回。
- 修法(统一写死):每个探针点**先探针、后存档**;只把"探针通过"的 state 标记为合法回滚点;常驻保留最近 2 个合法点;回滚后立即复测探针确认恢复。这是三行代码的事,但不写就是假回滚。

### F7. "on-policy 所以 R-安全"成立但有衰减期限,各案步数边界认可

run-006/7/8 的 R-崩(0.95→0.2)是外生格式语料;E4 伤锚是 off-policy 补丁 @8e-5×60 步。本轮五案全部只用自产 trace、零新格式,**R-崩的第一死因已结构性排除**。LR×步数积对照事故(8e-5×60):02 是 1/18,03 是 1/48,01 是 1/4(60 步×2e-5,Leg-2 再加 50 步则达 ~1/2)。**01 是唯一逼近事故量级的案子**,且 MoE-LoRA-RL 无先例——其 KL 锚"默认关、熔断二次触发才开"过于自信:子采样 15% 的 KL 成本仅 ~$6/腿(recon_tinker §4 公式),对 $145 的腿这是必买的保险,**要求 Leg-1 从 step 0 默认开启**(coef 0.05、15% 子采样),而非事后补救。

2. **R1 骨架与 02 的安全参数冲突且自身有假回滚**:骨架用 LR 3e-5×~80 步(事故积的 1/2!)、探针 20 步一次 40 题 <95%、**循环内无 save_state**(`rollback()` 无目标,F6)。修法:R1 执行参数以 02 的 1.2e-5×22 步×62% 锚为准(或给出为何敢用 2.5 倍 LR×3.6 倍步数的论证),探针按 F2/F3 扩容并纳入 eq/bit,save_state 按"probe→pass→save"写死。
3. **D3 consolidation 训 holdout 猎物的后果要预登记**:这对 LB 无泄漏(holdout 本来就是 train 切片),合法;但训完后 holdout 仪器报废,任何 post-D3 回归只能靠 LB 粒度 0.01 的仪器看(F5)。必须预登记:D3 之后不再做任何"holdout 增益"声明;pre-D3 最佳挑战者的提交物理保留,作 D3 翻车时的 final selection 候选。
4. **G0 增项(F1)**:官方判分语义审计(fallback 重打分 + 二进制守卫钉死)写进 G0 免费清单——它直接改写 P1(bit 32 题)这个全账本最大单块的分母,比"世界 A/B"判定同等优先。
5. 轻微:M0 用 holdout 猎物采样做覆盖测量(只测不训)合规;但 G1/G2/全局线反复消费同一 64 题猎物名单,挑选效应会让"净翻转 +5 题"略虚——预登记时把全局线的 +5 理解为名义值,LB 终审地位不变(手册已这么写,保持)。
